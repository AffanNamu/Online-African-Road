# UI art, fonts and login setup

Everything the login screen shows is loaded from `Assets/_Project/Resources/UI/` at runtime, so art can be swapped by replacing a file
(same name, same type). Nothing needs to change in code.

| File | What it is | Replace with |
|---|---|---|
| `login_bg.jpg` | Full-screen backdrop (cover-fitted to any screen shape) | Your own 1920x1080+ key art, **without** UI or third-party logos baked in |
| `logo_mark.png` | The gold "A" + Africa mark (top-left) | Transparent PNG, square |
| `icon_*.png`, `feat_*.png` | White/gold glyphs, tinted in code | Same names, transparent PNG, 128px+ |
| `Fonts/Montserrat-*.ttf` | Brand type (SIL Open Font License, see `Fonts/OFL.txt`) | Any TTF with the same file names |

The shipped `login_bg.jpg`, `logo_mark.png` and icons are **placeholders generated by code** (`tools/gen_login_bg.py`,
`tools/gen_ui_icons.py`, deterministic) so the repo contains no third-party imagery. Regenerate with `python3 tools/gen_ui_icons.py`.

## National flags
`Assets/_Project/Resources/Flags/{iso2 lower case}.png` (96x72, 4:3): the 55 African states plus Western Sahara, rendered from [flag-icons](https://github.com/lipis/flag-icons) 7.2.3 (**MIT**, licence text kept next to the files, details and regeneration in `Flags/SOURCE.md`). They are real artwork from a third party, redistributable under that licence, so they live in this folder and not under `Assets/ThirdParty/`.
They are drawn only through `Ui.Flag` / `Ui.CountryTag` / `Ui.TextWithCountry`, which pick the file from the stored country code via `ARO.NetCore.CountryFlags` and nothing else (never a name, address or location). No country, a malformed code, or a code without artwork draws a neutral slate box with a globe (`FlagArt` returns null). Import settings (`FlagTextureImporter`): no power-of-two stretching, mipmaps, uncompressed. Unlike the other pictures these PNGs are stored in plain git, not LFS (`.gitattributes`, about 260 KB in all): the .NET tests decode them without an LFS fetch, and the session that added them could not push new LFS objects (the LFS endpoint answered 403). Moving them to LFS later only needs that line removed and `git add --renormalize`.

## Google / Apple sign-in
The buttons run a real OAuth redirect through Supabase. They only work once the provider is enabled **in your Supabase project**:

1. Supabase dashboard -> Authentication -> Providers: enable Google (needs a Google Cloud OAuth client) and/or Apple (needs an Apple Developer account).
2. Authentication -> URL Configuration: add the address the game is served from (e.g. `http://localhost:8000` and your public URL) to the redirect allow-list.

If a provider is not enabled the screen says "... sign-in is not enabled for this game yet" instead of failing. Unverified end to end:
CI cannot reach `*.supabase.co` and no provider has been configured yet.
