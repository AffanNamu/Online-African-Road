# Reference-to-asset production matrix

Generated by `tools/kano/make_city_plan.py`. **Status: planning. No asset below has a Blender source yet.** Each concept (R-006 to R-015, ChatGPT-generated, the owner's compulsory design standard) is a design specification to reproduce in genuine 3D geometry; it is never placed on a plane, used as a texture or shipped. Where the game cannot yet reproduce something, the engine gap is named (RB items, `docs/ROAD_ENGINE_BACKLOG.md`) and the deviation is explained instead of silently simplified.

**95 assets**: GLOBAL 70, REGIONAL 10, CITY_SPECIFIC 9, LANDMARK 6; 76 backed by a concept, **19 blocked** (no concept or verified reference yet; nothing is invented for them).

Classes: **GLOBAL** (`aro_`) reusable across most cities; **REGIONAL** (`rg_<region>_`) for a geographic or architectural region (`ngn` = Northern Nigeria); **CITY_SPECIFIC** (`kano_`) designed for one city; **LANDMARK** (`lmk_kano_`) a distinctive real location, never copied to another city.

Status vocabulary (an asset moves through these in order and never skips): needs_concept -> concept_approved -> blockout_completed -> detailed_modelling_completed -> materials_completed -> blender_validation_passed -> unity_import_verified -> in_game_visual_review_passed -> production_approved.

## Common tasks for every asset

**Blender:**

1. write the concept down as a table of proportions, materials and details; the owner corrects it
2. blockout from reusable kit modules; render at the reference camera and compare
3. detail modelling: real walls, roofs, openings, structure and ornament (no image planes)
4. UV unwrap and PBR material set (shared M_<surface> names; atlas per family)
5. LOD chain (prefab LOD0 and LOD1; merged tiers come from the baker) and collision (box or convex, never the render mesh)
6. validate_asset against the game's budgets
7. save a versioned .blend and export FBX and GLB with a manifest

**Unity:**

1. Unity import test (orientation, scale, materials, collision, LOD thresholds)
2. prefab build (identity root, own LODGroup and BoxCollider, shared-kit materials)
3. catalogue entry and placement data
4. in-game screenshot from the reference camera and side-by-side comparison; deviations recorded
5. performance measurement ([Perf] draw calls, triangles, texture memory)
